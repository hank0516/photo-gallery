# Implementation Plan: Video Upload & Playback

**Branch**: `003-video-support` | **Date**: 2026-08-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-video-support/spec.md`

---

## Summary

Extend the existing photo gallery to support video uploads (MP4, MOV, WebM, AVI up to 500 MB).
On upload the backend extracts the first video frame via `ffmpeg` and stores 300 px / 800 px
thumbnails to Linode Object Storage — reusing the existing `_make_thumbnail()` helper. A new
`mime_type` column on the `photos` table is the sole discriminator: the frontend checks
`mime_type.startsWith('video/')` to render a play-icon overlay in the grid and an HTML5 `<video>`
player in the lightbox. All other features (search, download, delete, caption) work without changes.

---

## Technical Context

**Language/Version**: Python 3.12 (backend) · Node 20 + Vue 3 (frontend)

**Primary Dependencies**:
- Backend: FastAPI, SQLAlchemy 2, Alembic, Pillow, `ffmpeg` (system package via `apt`)
- Frontend: Vue 3, Pinia, Axios (no new packages)

**Storage**: MariaDB (metadata), Linode Object Storage (video + thumbnail files)

**Testing**: Manual validation per `quickstart.md`; existing test suite is not extended (no automated tests exist)

**Target Platform**: Linux/Debian server + modern browsers (Chrome, Safari, Firefox, mobile)

**Performance Goals**:
- 100 MB MP4 uploads and appears in grid in < 90 s on standard broadband
- Video begins playing in lightbox within 3 s of click

**Constraints**:
- No video transcoding or streaming (HLS/DASH). Direct presigned URL playback only.
- No new npm packages.
- `ffmpeg` must be installed as a system package (not pip).

**Scale/Scope**: Private system < 50 users. No concurrency concerns.

## Phase 0: Research

All decisions documented in [research.md](research.md). Summary:

| Question | Decision |
|---|---|
| Video thumbnail tool | `ffmpeg` via `subprocess`; Pillow resizes output |
| Schema approach | Add `mime_type VARCHAR(100) NULL`; make thumb keys nullable |
| Video size limit | New config `max_video_mb = 500` |
| Supported MIME types | `video/mp4`, `video/quicktime`, `video/webm`, `video/x-msvideo`, `video/avi` |
| Upload queue preview | Generic video icon SVG (not `<img>` with blob URL) |
| Lightbox video source | `original_url` from `GET /photos/{id}` (same fetch as images) |

## Phase 1: Design & Contracts

### Data Model

See [data-model.md](data-model.md).

**Summary of changes**:
- `photos.mime_type VARCHAR(100) NULL` — new column (discriminator)
- `photos.thumb_300_key`, `photos.thumb_800_key` — changed from NOT NULL to nullable
- `config.py` — new `max_video_mb: int = 500`

### API Contract

See [contracts/api.md](contracts/api.md).

**Summary of changes** — `mime_type` added to 4 response shapes:
- `POST /albums/{id}/photos` upload response
- `GET /albums/{id}` photo list items
- `GET /photos/{id}` detail response
- `GET /search` result items

### Quickstart Validation

See [quickstart.md](quickstart.md). Seven scenarios cover: upload, playback, format rejection,
size limit, photo regression, search, and failed-thumbnail fallback.

## Implementation Phases (for `/speckit-tasks`)

The following phases are sequenced by dependency. Each phase is independently testable.

### A — Database & Model (backend foundation)
1. Write Alembic migration: add `mime_type`, make thumb keys nullable
2. Update `Photo` model: `mime_type` field, nullable thumb keys
3. Update `config.py`: `max_video_mb = 500`
4. Run migration; verify schema

### B — Backend Upload (server-side video handling)
5. Expand `ALLOWED_TYPES` in `photos.py` to include video MIME types
6. Implement `_extract_video_thumbnail(raw_bytes, ext) -> (bytes | None)` using ffmpeg subprocess
7. Branch upload logic in `upload_photo()`: image path unchanged; video path calls thumbnail extractor, sets `mime_type`, skips EXIF/width/height
8. Update upload response to include `mime_type`

### C — Backend Response Propagation
9. Add `mime_type` to photo list items in `albums.py` `get_album()`
10. Add `mime_type` to photo detail in `photos.py` `get_photo()`
11. Add `mime_type` to search results in `search.py`

### D — Frontend: Upload Zone
12. Update `UploadZone.vue` `accept` attribute to include video types
13. Update `addFiles()` filter to allow video MIME types
14. Add video preview (generic icon) for video items in the queue
15. Update hint text to mention video formats and 500 MB limit

### E — Frontend: Grid
16. Update `PhotoGrid.vue` to render play-icon overlay when `item.mime_type?.startsWith('video/')`
17. Handle null thumbnail: show placeholder when `thumb_300_url` is null

### F — Frontend: Lightbox
18. Update `Lightbox.vue` to conditionally render `<video>` vs `<img>` based on `mime_type`
19. Set `<video>` `src` from `original_url` (fetched via `GET /photos/{id}`)
20. Add auto-pause when navigating away from a video (use `videoEl.value?.pause()`)
21. Handle null thumbnail in `displayUrl` fallback

### G — Validation
22. Apply migration on server, restart backend, rebuild frontend
23. Run through all 7 scenarios in `quickstart.md`
